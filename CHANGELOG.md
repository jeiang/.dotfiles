# Changelog

## Unreleased

### Added

- `docs/adr/0011-extend-the-scoped-credential-agent-into-a-tiered-fleet-operator.md`: records the three-tier fleet-operator model (free/soft-confirm/forbidden, enforced by the `hermes-ops` doas allowlist), the private-network SSH transport decision, and the new credential inventory (Actual Budget, iCloud CalDAV, a second GitHub PAT, Grafana annotations) for the upcoming Hermes fleet-operator expansion. `CONTEXT.md` gains "Fleet Operations Tiers" and "hermes-ops" glossary entries; `docs/runbooks/hermes.md` gains skeleton "Credential inventory and rotation" and "Verifying the operations tiers" sections.
- `modules/nixos/hermes-ops/default.nix`: the fleet-wide `hermes-ops` unprivileged user and its per-node doas allowlist (ADR 0011's Fleet Operations Tiers classifier), wired onto all four Legion nodes by `modules/hosts/legion/default.nix`. Each node declares its tier-1/tier-2 systemd unit lists as data; `systemctl start`/`restart` doas rules are generated per unit (identical for both tiers -- the confirm gate is prompt-level), `systemctl stop` for every listed unit, and `netbird status`/a single-purpose `netbird expose` wrapper (verified against the pinned netbird 0.76.1 CLI). legion-node3 additionally grants the same rules to the `hermes` service user for node-local doas without SSH-to-self. `docs/runbooks/hermes.md`'s "Verifying the operations tiers" section is filled in with exact commands.
- `modules/nixos/hermes/default.nix`: the Hermes-side half of ADR 0011's `hermes-ops` fleet-execution transport -- a new `hermes/ssh-key` sops secret installed (overwrite-on-start) to `${stateDir}/.ssh/id_ed25519`, plus a Nix-managed `${stateDir}/.ssh/config` with per-node `Host` blocks for legion-node1/2/4 (no committed Legion SSH host keys exist to pin against, so host-key verification uses `StrictHostKeyChecking accept-new` against a persistent `known_hosts`, documented tradeoff in-module and in the runbook) and `pkgs.openssh` added to `extraPackages`. Also declares `settings.memory.nudge_interval = 10` and `settings.skills.external_dirs` pointing at the Knowledge Base clone's `skills/` (both verified against `cli-config.yaml.example` at the pinned hermes-agent rev). `SOUL.md` gains the fleet-operations tier policy and a much stronger knowledge-discipline section (write during conversations, Obsidian-vault conventions, a starting folder taxonomy); `SERVERS.md` gains the exact per-node tier table, doas invocation forms, expanded VictoriaLogs LogsQL examples with real journald field names, the journalctl fallback, and `netbird expose`'s foreground/backgrounding and stop/list mechanics (verified against the pinned netbird 0.76.1 source -- no list/stop subcommand exists). `docs/runbooks/hermes.md`'s credential-inventory entry for the SSH key is filled in with the concrete secret name, install path, and host-key-verification note.
- `modules/packages/actual-cli.nix`: a standalone Nix packaging of the official `@actual-app/cli` npm package (verified as the exact CLI the `actual-budget-import` skill targets) via `buildNpmPackage` against a synthetic single-dependency lockfile (`modules/packages/actual-cli/`) -- npm resolves `@actual-app/api`'s `workspace:*` dependency to its published registry version for an external install, avoiding the upstream yarn-workspace monorepo's own build toolchain entirely. `better-sqlite3`'s native install script builds fully offline via `buildNpmPackage`'s own `node-gyp`-against-Nix-headers path.
- `modules/nixos/hermes/default.nix`: five personal-service integrations for the Hermes fleet-operator (docs/adr/0011). **Actual Budget** (feature 3): the new `actual-cli` package added to `extraPackages`, `ACTUAL_SERVER_URL` set directly (non-secret), `ACTUAL_SESSION_TOKEN`/`ACTUAL_SYNC_ID` folded into the existing `hermes/env` sops secret. **iCloud Calendar** (feature 8): `khal`/`vdirsyncer` added to `extraPackages`, a Nix-rendered vdirsyncer config (single-sided `collections = ["from b"]` to keep `discover` non-interactive) referenced directly from the Nix store via `VDIRSYNCER_CONFIG`, a Nix-managed khal config installed to its default path by preStart, and a new `hermes-vdirsyncer-sync` oneshot+timer (15m cadence, mirrors `hermes-kb-sync`'s shape) using `ICLOUD_USERNAME`/`ICLOUD_APP_PASSWORD` (also folded into `hermes/env`) via vdirsyncer's `password.fetch`/`username.fetch` "command" strategy. **artemis LLM provider** (feature 7): a `settings.providers.artemis` custom OpenAI-compatible entry pointed at llama-swap's raw NetBird peer IP (not the mesh DNS name, for reachability when the mesh itself is degraded), no credential, a 600s `request_timeout_seconds` for cold model loads, and verified never reachable through the automatic fallback chain (`hermes_cli/fallback_config.py` reads only `fallback_providers`/`fallback_model`, neither touched here) -- manual `/model`/`--provider` switch only. **Other Git repos** (feature 9): `HERMES_REPOS_TOKEN` (folded into `hermes/env`) for the agent's own interactive `gh`/`git` against four repos beyond the Knowledge Base, used explicitly per-command so the existing `GITHUB_TOKEN`/`hermes-kb-sync` path is unaffected -- no new sync unit, deliberate-commit discipline per ADR 0011. **Grafana annotations**: `GRAFANA_URL` set directly (non-secret, loopback) and `GRAFANA_ANNOTATION_TOKEN` (folded into `hermes/env`) for the agent's own `curl` POSTs to `/api/annotations`. No new `sops.secrets` entries -- all six new credential/config values fold into the existing `hermes/env` secret. `SOUL.md` gains an expanded "GitHub access" section (two tokens, used explicitly) and a "Calendar" note; `SERVERS.md` gains "Budget (Actual)", "Calendar", "Alternative model (artemis)", "Other Git repos", and "Grafana annotations" sections; `docs/runbooks/hermes.md`'s credential-inventory entries are filled in with exact secret line names, mint/rotate steps, and consumption points, plus a consolidated pre-deploy `hermes/env` checklist.
- Zakkart: a nix-darwin host for the macOS workstation (`modules/hosts/zakkart/`, `modules/darwin/`), managed with Determinate Nix (ADR 0008) and nixpkgs-first application sourcing with Homebrew/App Store exceptions (ADR 0009). Includes a `just darwin-switch` recipe, a `checks.aarch64-darwin.zakkart-system` CI check built on a hosted macOS runner, and `docs/runbooks/zakkart-bootstrap.md`.
- Zakkart macOS preferences (`modules/darwin/preferences.nix`): dock moved right with autohide and hot corners, menu bar mirroring the observed macOS 26 values, pink accent/highlight colors, the application firewall, the repo's `assets/wallpaper.jpg`, Helium as the default browser via `defaultbrowser`, the built-in display scaled to "More Space" via `displayplacer`, and the Spotlight (Cmd+Space) hotkey disabled — per `docs/adr/0010-script-user-scoped-macos-preferences-nix-darwin-cannot-express.md`.
- Zakkart: hide recent/suggested apps in the dock (`dock.show-recents = false`) and set the window title bar double-click action to Fill (`AppleActionOnDoubleClick`, no nix-darwin option on the pinned rev).
- Adopt Determinate Nix on the NixOS fleet (legion-node1..4, artemis) by importing Determinate's NixOS module in `modules/nixos/nix.nix` -- per ADR 0011, this keeps the existing `nix.settings` working unchanged (rendered to `/etc/nix/nix.custom.conf`).

### Fixed

- Prepend the nix-darwin profile paths (`~/.nix-profile/bin`, `/etc/profiles/per-user/$USER/bin`, `/run/current-system/sw/bin`, `/nix/var/nix/profiles/default/bin`) in the wrapped fish's darwin config -- macOS login shells start from `path_helper`'s PATH, so `environment.systemPackages` tools (first symptom: `direnv hook fish` at startup) were unreachable. Linux config text is unchanged.
- Add the operator account to `users.knownUsers` (uid 501) on zakkart so the wrapped-fish login shell actually applies -- nix-darwin only writes `UserShell` for known users, so the previous bare `users.users.<name>.shell` was silently ignored and the account stayed on `/bin/zsh`.
- Declare `trusted: true` on every Brewfile tap entry so Homebrew >= 6.0's tap-trust enforcement doesn't refuse to load formulae/casks from the pinned third-party taps (`netbirdio/tap`, `can1357/tap`, `k06a/tap`) during activation.
- Move the host toolbox out of the wrapped Fish shell and use Cachix's pinned binary package to avoid IFD evaluation.
- Replace the pinned-store-path Cachix package (`builtins.storePath`, impure) with nixpkgs' `pkgs.cachix` — the pinned paths were old Hydra builds of the same 1.11.1 `-bin` output already cached on cache.nixos.org — and drop `--impure` from CI now that nothing violates pure evaluation.
- Export `DIRENV_CONFIG` in the wrapped fish's darwin login shells -- the wrapped fish never sourced nix-darwin's `set-environment`, so nix-direnv's loader (`/etc/direnv/direnvrc`) never loaded and `use flake` silently fell back to direnv's builtin, uncached implementation, re-evaluating dev shells on every prompt.
